# בדיקות

הסקריפטים כאן בודקים את האתר ואת מסך הניהול בדפדפן אמיתי (Chromium), בלי לגעת במסד הנתונים האמיתי:
כל קריאה של הדפים למערכת התורים נענית מקומית, עם לקוחות ותורים מומצאים.

פעם אחת, בתיקייה הזו: `npm install axe-core @electric-sql/pglite` (בודק הנגישות, ו-Postgres קטן שרץ בתוך Node לבדיקת קובצי מסד הנתונים). צריך גם Python עם Playwright ו-Chromium.

מריצים מתיקיית השורש של המאגר, אחרי כל שינוי ולפני העלאה:

    python3 tools/tests/check_public.py         # כל הדפים הציבוריים בארבעה רוחבי מסך
    python3 tools/tests/check_admin_flows.py    # מסך הניהול: יומן, סיום טיפול, לקוחה חדשה, מתנה, חיפוש, מחיקה
    python3 tools/tests/check_admin_marks.py    # מסך הניהול: הסימון «לא לשלוח הזמנות»
    python3 tools/tests/check_booking.py        # טופס קביעת התור מההתחלה עד הסוף, עם התיבה «לא לשלוח לי הזמנות» ובלעדיה
    node tools/tests/check_db.mjs               # קובצי מסד הנתונים: המיגרציה האחרונה, הביטול שלה והתקנה מאפס, על מסד ניסיון

כל סקריפט מסתיים ב-`PROBLEMS: 0` או ב-`ALL PASSED` כשהכול תקין.

`check_db.mjs` בונה את המסד כפי שהיה לפני המיגרציה האחרונה (מתוך git), מריץ עליו את המיגרציה ועובר על קביעת תור, כרטיסיות והרשאות. כשמוסיפים מיגרציה חדשה מעדכנים בראש הקובץ את שלושת השמות (`MIG`, `UNDO`, `BEFORE_REF`).

- `harness.py` שרת מקומי לקובצי האתר, מערכת תורים מדומה לדפים הציבוריים, והרצת axe.
- `admin_harness.py` מסד נתונים מדומה למסך הניהול (כניסה, לקוחות, הגדרות, תורים, עדכונים חיים). הוא שומר על הסימון «לא לשלוח הזמנות» כמו המסד האמיתי.
